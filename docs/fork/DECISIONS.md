# Implementation decisions

Decisions made while building Meditejo, newest last. Product decisions live in `BRIEF.md`; this file holds the implementation calls made on the way, with the reason for each, so they can be revisited deliberately. Mark a decision **provisional** when it waits on Burooj.

## 2026-10-15

- **Flutter 3.47.2 / Dart 3.13.2**, matching `flutter-version` in `.github/workflows`. On bjslab it is installed under the user at `~/.local/share/flutter`, with `flutter` and `dart` symlinked into `~/.local/bin`.
- **The Dart package keeps the name `medito`.** Renaming it would rewrite every `package:medito/` import, conflict with all concurrent work, and make cherry-picking from upstream expensive. Users see the display name, application ID and icons, which do change.
- **Application ID `io.github.beejsbj.meditejo`** (provisional). It is a reverse domain Burooj controls through GitHub, and F-Droid accepts it. Pick it before the first phone install, because changing it later means installing a separate app.
- **One durable signing key, kept on bjslab.** Every APK installed on the phone is signed with the same Meditejo key, because a key change forces an uninstall, which deletes the local-only stats and favourites. The key never goes to Daytona: the cloud builds the APK and bjslab signs it with `apksigner`. Whether to back it up to BWS is Burooj's call (provisional).
- **Build route:** resolve dependencies on bjslab, where pub.dev is reachable, and ship the pub cache with the Daytona upload (`--profile android`), where pub.dev is blocked. Gradle and the Flutter engine artifacts download inside the sandbox. Details are in `BUILD.md` once the route is proven.
- **Medito mock mode is the baseline, built but not installed.** The phone's remote-control MCP has no uninstall tool, so only Meditejo-named builds with the durable key go onto the phone.
- **Placeholder icon** until Burooj chooses a mark. This is a design decision to make later, not part of the build.
- **Build sandbox inputs and signing (build worker):** stage selected source plus a tarball containing only resolved pub.dev package sources/hashes, including ignored generated Dart files explicitly. Request the account's maximum 10 GiB per sandbox (25 GiB was rejected) and cap Gradle at two workers with a 4 GiB heap. Supply the base Android application ID as a build-script argument through sandbox-only `keystore.properties`; create Firebase placeholders and disposable signing credentials only there. The durable RSA-4096 key lives under `~/.config/meditejo/signing/` on bjslab, and only local `zipalign`/`apksigner` use it. This preserves the signing boundary and avoids committing credentials or host-specific Gradle settings. See `BUILD.md` for verification and limitations.
- **Stage Gradle plugin portal artifacts over HTTPS (build continuation):** the portal returns HTTP 200 on bjslab but resets TLS connections from Daytona, while Maven Central remains reachable. Fetch only exact coordinates established by Gradle's missing-artifact output, starting with the Kotlin DSL 5.2.0 marker and implementation. Upload the resulting local Maven repository and put it first via a sandbox `beforeSettings` init script, including Flutter's included build. This keeps Gradle off bjslab and leaves tracked Gradle files unchanged; regular transitive dependencies resolve from reachable Google Maven/Maven Central.
- **Prune disposable SDK contents to fit the 10 GiB cap:** after plugin resolution passed, Gradle's caches filled the disk before app compilation. Use the same Gradle version's binary distribution and remove unused SDK/web/profile/development caches in the sandbox, retaining all Android ABIs and the requested build mode. This changes neither app code nor toolchain versions; the downloadable SDK remains complete on bjslab.
- **Build the de-Medito source for arm64 (supersedes the mock baseline/all-ABI proof):** use `--source CHECKOUT` to stage any resolved/generated checkout without copying the scripts into it. The current proof targets PR #3 at `37548a25`, dev/debug, without mock mode, and keeps only arm64 target artifacts. NDK 28.2 remains necessary: `path_provider_android 2.3.1` depends on `jni 1.0.0`, whose Android CMake build compiles C. Remove only unused target sysroot libraries, keep shared headers/host tools, disable Gradle build caching/daemon and delete its unpacked distribution archive. Stage and periodic `du` measurements are collected with the job, so capacity conclusions have evidence. These footprint changes remain sandbox-only; a phone install still waits for rename/integration.
- **Omit blocked JitPack/JCenter repositories at sandbox task resolution:** the arm64 de-Medito build reached Java compilation with 574 MB still free, then `integration_test` failed listing the dynamic `androidx.test:runner:1.2+` version because Gradle queries every repository's metadata. The init script removes those two blocked project repository hosts after project configuration; Google Maven and Maven Central remain. No dependency version or tracked Gradle file changes. A dependency genuinely hosted only there will still require an explicit artifact handoff rather than silently changing its version.
